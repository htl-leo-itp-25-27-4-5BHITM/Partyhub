Was ist CI/CD?

Drei Begriffe, die aufeinander aufbauen

🔁

Continuous Integration

Jede Änderung wird automatisch gebaut und getestet, sobald sie ins gemeinsame Repo kommt.

„Funktioniert mein Code mit dem der anderen?“

📦

Continuous Delivery

Nach grünen Tests entsteht automatisch ein auslieferbares Paket. Ausrollen per Klick.

„Wir könnten jederzeit ausliefern.“

🚀

Continuous Deployment

Das Paket wird ohne manuellen Schritt in Produktion ausgerollt.

„Jede grüne Änderung ist sofort live.“

Wie hängen die Workflows zusammen?

test.yml 

name: Test
on:
  pull_request:
    branches: [ "main" ]
  push:
    branches: [ "main" ]
jobs:
  test:
    steps:
      - run: node --test …
      - run: mvn clean test
      - run: npx httpyac --all *.http
→
push.yaml 

name: Build and Push
on:
  workflow_run:
    workflows: [ "Test" ]
    types: [ completed ]
jobs:
  build-and-push:
    # nur wenn Test grün und Branch main
    steps:
      - run: mvn -B package -DskipTests
      - uses: docker/build-push-action@v5
  deploy:
    needs: build-and-push
    uses: ./.github/workflows/deploy.yml
→
deploy.yml 

name: Deploy
on:
  workflow_call:
    inputs:
      image-tag: { type: string }
jobs:
  deploy:
    steps:
      - run: kubectl apply -f k8s/
      - run: kubectl set image
          deployment/quarkus quarkus=…:$TAG
      - run: kubectl rollout status
          deployment/quarkus

on: pull_request / push startet bei jedem PR und Merge

workflow_run startet, wenn „Test“ fertig ist

workflow_call wird von „Build and Push“ aufgerufen

Gekürzt. Vollständig in .github/workflows/.

Umsetzung

Ein minimaler CI-Workflow

.github/workflows/test.yml

name: Test
on:
  pull_request:
    branches: [ "main" ]
  push:
    branches: [ "main" ]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-java@v4
        with: { distribution: temurin, java-version: '21' }
      - run: mvn clean test

on · Wann?

Bei jedem Pull Request und jedem Push auf main.

runs-on · Wo?

Auf einem frischen Ubuntu-Rechner von GitHub, dem Runner.

uses · Fertige Bausteine

Code auschecken, Java 21 installieren.

run · Eigener Befehl

Tests ausführen. Schlägt er fehl, ist der Lauf rot ✗.
