## Accepted access and state contract

| Operation | Accepted actor/access | Success state | Denied or failed state |
|---|---|---|---|
| List/serve public-party media | Anonymous or authenticated caller | Return only the owning public party's server-backed items/bytes. | Missing party/item/file produces an unavailable result, not successful broken content. |
| List/serve private-party media | Authenticated host, pending invitee or joined attendee | Same bounded list/item result as public media. | Anonymous/unrelated callers receive no list, bytes, uploader or storage reference. |
| Query a user's media | Caller may receive only items whose owning parties they can view | Projection preserves the party boundary item by item. | An uploader identifier never becomes a private-media bypass. |
| Upload party media | Authenticated party Viewer, at any party time | Valid non-empty JPEG/PNG/GIF/WebP up to 5 MiB receives a safe server reference and appears in the shared gallery. | Anonymous public viewers, non-Viewers, invalid content and inconsistent storage/persistence create no usable gallery item. |
| View a profile picture | Authenticated profile viewer | Return the current validated image or stable placeholder with a bounded refresh reference. | Anonymous requests are rejected; unavailable custom content resolves to the placeholder without storage details. |
| Replace a profile picture | Authenticated Self | Valid image becomes the single current logical reference and clients refresh stale state. | Wrong actor, invalid input, storage failure or persistence failure leaves the previous usable picture unchanged. |
