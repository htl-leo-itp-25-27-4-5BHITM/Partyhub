## Integrated Group 6 disposition

The applied child establishes one visibility-first server query pipeline before search/filter/sort/pagination, strict AND composition, deterministic post-filter pagination, and explicit browser/iOS responsibility. PARTY-08-PARTY-11 and RADIUS-01-RADIUS-03 are scoped to the iOS home map; unlimited radius applies no distance predicate, unavailable user location resets finite radius, and reset/results/summary/visualization stay synchronized. A party without matching displayable theme metadata is excluded whenever a theme filter is active; another active filter cannot include it.

## Integrated Group 7 disposition

The applied child establishes that gallery lists, item bytes and user-media projections reuse the D007/D017 Viewer predicate; public media remains anonymously viewable, while Q005 is resolved by requiring authenticated Viewer identity for upload. MEDIA-03 accepts non-empty JPEG/PNG/GIF/WebP content up to 5 MiB, safe server references and no usable item after inconsistent storage. Shared gallery state is server-backed; inspected iOS local photo files stay local until synchronized. SOC-07 makes profile pictures authenticated profile content, self-managed with the same validation boundary, stable placeholder/refresh behavior and preservation of the prior usable picture on replacement failure. Physical deletion, retention and orphan cleanup stay with Q006/Step 11.

## Integrated Group 8 disposition

The applied child makes SOC-03's follow, invitation, attendance and party-event recipients deterministic and suppresses events for denied, failed and repeated no-op actions. SOC-08 accepts typed recipient-scoped center state and separates informational read/delete from authoritative domain actions. SOC-09 accepts same-user effective defaults plus independent channel/category gates while keeping pending actions available. SOC-10 supports in-app and email with failure isolation and stable event-recipient/channel identities; push and SMS remain unsupported until integrated. SOC-11 bounds welcome and weekly digest email behavior and requires per-recipient Viewer filtering. Q006 retains physical retention, delivery receipts, retry timing and reliability policy; Q014 retains exact route/schema/status choices.

## Integrated Group 9 disposition

D021 closes Q001 by deferring QR login rather than accepting either observed source path. The supported identity baseline remains AUTH-01-AUTH-12: Keycloak authorization code with PKCE, validated bearer identity, backend subject linkage and token-backed native sessions. The numeric-user QR/deep-link path and the disconnected stored-token/custom-HMAC path provide no accepted credential or authorization semantics. Group 9 therefore adds no product requirement and changes no main spec; [qr-login.md](qr-login.md) keeps all six endpoints, storage, browser/iOS/email consumers and tests visible. G007/G008/G046-G050 bound later retirement/containment or a separately proposed replacement.

## Integrated Group 10 disposition

D022 closes Q002 through PARTY-17-PARTY-19. Current device location remains private client context for accepted iOS distance/radius behavior and explicitly enabled local visit detection; server user/attendee location sharing remains unsupported. Visit history is permission-gated, device-local and separate from authoritative attendance. Calendar export is a user-controlled local snapshot without automatic PartyHub synchronization. [Extended-client evidence](extended-client-features.md) keeps the exposed routes, clients, permission declarations and test limits visible, while G051-G056 bound later containment and implementation work.

## Integrated Group 11 disposition

D023 and ENV-08-ENV-11 make the local environment deterministic for real-token verification: one realm source, runtime issuer binding, the native client and a non-authoritative bypass. D024 closes the singular-route and phantom-route part of Q014 without adding server routes. D025 maps Q006 onto existing accepted requirements and replaces it with Q015-Q018. Deployment reset (G057), gallery storage (G058), migrations (G059), destructive scripts (G060), CI gating and real-JWT evidence (G061), error envelopes (G062), stale OpenAPI (G063), guidance drift (G064), cleanup (G065) and the OpenSpec CLI difference (G066) stay implementation or tooling gaps.
